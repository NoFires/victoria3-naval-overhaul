Current Architecture

CodeGraph not available — structural analysis based on file/grep heuristics.

The codebase consists of two distinct runtime planes: (1) a Victoria 3 Clausewitz/Jomini Mod Payload spanning 17 script, GUI, localization, and metadata files across common/, events/, gui/, localization/, and .metadata/; and (2) an Offline Python Verification & Combat Sandbox (sim_overhaul.py) that reads Vanilla 1.15.1, companion mods (Kuromi AI, Naval Treaty Expanded), and this mod directly from disk to validate VFS merging, UTF-8 BOM encoding, localization coverage, tech-tree closure, AI ship designer picks, and 6-step naval combat balance.

Note: During this review engagement, critical engine-level defects discovered across subsystems B–F were also remediated and verified via python -B sim_overhaul.py --assert-mode. The current-state diagrams and criteria sections below document the baseline findings uncovered in the audit alongside the architectural posture and remaining strategic improvements.

Separation of Concerns

Strength
Clean Physical Separation Between Mod Payload and Dev Tooling

Game-loaded Clausewitz assets (common/, events/, gui/, localization/, .metadata/) are cleanly isolated from Python simulation tooling (sim_overhaul.py) and documentation (AGENTS.md, plan.md, docs/) via selective NTFS junctions, preventing developer artifacts from leaking into Steam Workshop uploads.

Concern
Supply Ship Non-Combat Logistics Mixed With Armed Combat Slots

In the audited baseline of common/ship_types/00_ship_types.txt:2675-2707, ship_type_supply_ship had been assigned ship_mod_slot_hull and ship_mod_slot_secondary (ship_mod_secondary_standard), injecting artillery goods consumption and combat firepower/screening into pure logistics vessels. (Remediated by restoring Vanilla's 4 unarmed logistics slots.)

Concern
Monolithic Responsibilities Inside sim_overhaul.py

sim_overhaul.py (877 LOC baseline) mixes Clausewitz lexical parsing, VFS overlay resolution, 6-step naval combat physics, economic/tonnage calculation, AI designer heuristics, and regression assertion reporting in a single script file without module boundaries.

Cohesion and Coupling

Strength
Cohesive 4-Pole Tactical Partitioning Across Utility Slots

Utility modifications in 03_overhaul_utility_modifications.txt and 00_ship_types.txt are strictly partitioned across utility_1 (sensors/fire control), utility_2 (survivability/stealth), utility_3 (special armament/AA/minesweeping), and utility_4 (endurance/landing ops), eliminating multi-slot self-stacking exploits across all 22 ship types.

Risk
Full-File Shadowing Coupling in 00_ship_types.txt and 00_ship_modification_slots.txt

common/ship_types/00_ship_types.txt (2,708 lines) and common/ship_modification_slots/00_ship_modification_slots.txt replace entire Vanilla files. Any Victoria 3 patch (e.g., 1.15.x hotfixes) or companion mod modifying Vanilla ship types in the same file faces load-order shadowing unless converted to INJECT: / REPLACE: per-ship directives or paired with an explicit compatibility patch.

Concern
Tight Coupling Between GUI Template Context and ShipType vs. ShipTemplate

In gui/ship_designer_popup.gui:894, the baseline bound the anti-ship modifier block to static [ShipType.GetModifier] rather than [ShipTemplate.GetModifier], decoupling modification-granted accuracy bonuses (ASW depth charges, sonar, torpedo defense) from live UI feedback. (Remediated to [ShipTemplate.GetModifier].)

Layered Architecture

Strength
Clear Script Layering via Jomini Prefix Conventions

Overlay files consistently use zz_ ASCII filename prefixes (zz_naval_overhaul_script_values.txt, zz_naval_overhaul_strategy.txt, zz_naval_overhaul_navy_model.txt, zz_naval_overhaul_missions.txt) so patches apply deterministically after Vanilla and companion mods such as Kuromi AI.

Concern
Presentation-Layer Duplicate Texture & Localization Leakage

In the baseline, 00_ship_modification_slots.txt assigned the identical supplies_navy.dds icon to five separate slots (range and utility_1..4) and duplicated armor_navy.dds and average_damage_navy.dds, weakening visual hierarchy in the GUI layer. (Remediated with 10 distinct verified Vanilla icons.)

Hexagonal Architecture / Ports and Adapters

Strength
Non-Destructive TRY_INJECT Adapters for Companion Mods

Laws (zz_naval_overhaul_navy_model.txt) and naval missions (zz_naval_overhaul_missions.txt) interact with Vanilla and external political/naval mods through TRY_INJECT: adapters, degrading gracefully if another overhaul renames or removes a target law without throwing VFS errors.

Concern
Hardcoded Developer Filesystem Paths in sim_overhaul.py Adapter

Baseline sim_overhaul.py:20-23 hardcoded C:\Users\RedAndBlack\... and Steam workshop IDs with no CLI flags or environment variable fallback, preventing external contributors from running the simulator without editing source code. (Remediated with --vanilla-dir, --kuromi-dir, --nte-dir, and V3_*_DIR environment variables.)

Scalability

Strength
Bounded Monthly Country Pulse & Cooldown-Gated Construction Hooks

common/on_actions/01_naval_overhaul_on_actions.txt avoids expensive global ship iteration by checking aggregate navy_size thresholds and gating on_ship_constructed with a 365-day country variable cooldown.

Risk
Unbounded naval_battle_size Addition & GUI 2-Row Core Slot Cap

Baseline REPLACE:naval_battle_size added the detection/visibility ratio term directly onto post_command_limit_base_amount_cap without clamping the final sum against num_ships_not_in_battle or the admiral's command_limit_num_units. Additionally, gui/ship_designer_popup.gui:100-105 capped expanded core slots at 2 rows (148px), overflowing if any slot exceeds 6 options. (Both remediated.)

Observability

Risk
Guaranteed error.log Missing Localization & Blank Tooltip Breakdowns

The audited baseline referenced naval_overhaul_arms_race_momentum in 01_naval_arms_race_je.txt:26 without defining it in either English or Chinese localization, omitted a desc breakdown key in zz_naval_overhaul_script_values.txt:72-100, and duplicated utility_mod_scouting_seaplane on lines 52 and 77 of both YAML files. (All remediated and enforced in --assert-mode.)

Concern
No Automated Victoria 3 error.log Ingestion in Tooling

sim_overhaul.py audits static files offline but does not provide an optional parser for Documents/Paradox Interactive/Victoria 3/logs/error.log after live game launches to correlate runtime engine warnings with mod keys.

Security

Strength
Zero-Dependency Stdlib Tooling & Sandbox-Safe Offline Execution

sim_overhaul.py relies exclusively on Python 3 standard library modules with read-only file parsing and no network I/O, shell execution, or dynamic eval/exec, eliminating supply-chain and code-injection risks for contributors.

Reliability

Risk
Silently Ignored Legacy Modifier & Dropped Vanilla Utility Modules

zz_naval_overhaul_navy_model.txt:12 injected character_convoy_raiding_mult = 0.15—a legacy character-scoped modifier unused anywhere in Victoria 3 1.15.1—into law_jeune_ecole. Simultaneously, 00_ship_types.txt completely omitted Vanilla's utility_mod_searchlights (the sole counter to night/weather accuracy penalties) and utility_mod_camouflage from all 22 ships. (Both remediated.)

Risk
Missing Journal Entry Invalidation Exit & Re-Entry Guard

je_naval_arms_race lacked both a naval_arms_race_completed re-entry guard and an invalid_outcome exit when a nation loses all coastal states, risking stuck journal entries and duplicated 5-year shipyard throughput modifiers. (Remediated.)

Resilience

Strength
Defensive Guardrails Against Missing Scopes & Companion Mods

zz_naval_overhaul_script_values.txt explicitly guards exists = scope:military_formation, exists = scope:enemy_military_formation, and exists = scope:own_commander, clamping detection/visibility ratios to [0.35, 2.5] and denominators to min = 1 to prevent division-by-zero or runaway battle sizes.

Concern
Early-Game Economic Shock From Armed Supply Ship Defaults

Adding ship_mod_secondary_standard (10 artillery input) to ship_type_supply_ship created immediate artillery shortages in 1836 for nations lacking arms industries. Restoring Vanilla's unarmed 4-slot supply ship structure eliminates this systemic fragility.

Data Architecture

Risk
Ten Misleading Localization Descriptions Diverging From Script Source of Truth

Ten modification _desc entries in both English and Simplified Chinese YAML contradicted the actual modifier blocks (e.g., claiming supply cost reduction where only supply capacity increased, claiming crit/accuracy/hull-damage bonuses that did not exist, or citing convoy raiding on hydrophones). Furthermore, orphan key ship_mod_secondary_heavy_casemate remained in localization with no script definition. (All remediated.)

Concern
Inconsistent Static Modifier Naming Convention & Dead Keys

01_naval_overhaul_modifiers.txt mixed modifier_naval_* and naval_overhaul_* prefixes and retained an unreferenced, unlocalized naval_overhaul_victory_prestige entry. (Normalized to modifier_naval_* and pruned dead entry.)

Cost Efficiency (FinOps)

Risk
Severe Industrial Goods Underpricing of Custom Utility Modules

Vanilla utility modules in 01_utility_modifications.txt cost 105–375 total construction goods units (which directly drive shipyard maintenance and AI ship_mod_market_multiplier). Baseline 03_overhaul_utility_modifications.txt priced superior late-game modules 5x–8x cheaper (e.g., 20 radios vs. Vanilla's 130), undermining the mod's core "no free max-out" trade-off constraint. (Recalibrated to 85–140 goods units.)

Strength
Calibrated Modification Level Cost Exponent (1.028)

Reducing SHIP_CONSTRUCTION_COST_MODIFICATION_LEVEL_FACTOR from 1.05 (Vanilla 4-slot baseline: 1.05^8 = 1.477) to 1.028 (10-slot baseline: 1.028^14 = 1.472) preserves Vanilla ship construction cost curves without exponential build-time inflation.

Operability

Strength
Zero-Dependency Single-Command Regression Gate

Contributors can run python -B sim_overhaul.py --assert-mode with no virtual environment or external packages to audit VFS conflicts, BOM compliance, localization symmetry, tech-tree validity, and combat balance.

Concern
Stale Documentation Referencing Retired Tooling

AGENTS.md:21-22 referenced nonexistent files (app.py, v3_naval_sandbox.py, data.py, *.json), and plan.md contained conflicting define numbers and outdated Phase 4.5 to-do claims. (Synchronized with actual codebase.)

Deployment Architecture

Strength
Selective Junction Mapping & Multiplayer Sync Enforcement

Only runtime directories (.metadata, common, events, gui, localization) and thumbnail.png are linked to the Victoria 3 staging directory, while .metadata/metadata.json maintains multiplayer_synchronized = true and all scripts avoid non-deterministic UI/local state branches.

Concern
Empty Workshop ID & Duplicate Thumbnail Asset

.metadata/metadata.json:3 has "id": "" (pending initial Steam Workshop publish), and thumbnail.png is duplicated at both repository root and .metadata/thumbnail.png; additionally, no automated CI workflow validates PRs on GitHub without a local Windows Victoria 3 installation.

Event Architecture

Concern
Over-Broad on_ship_constructed Trigger & Double-Stacked Arms Race Buff

on_ship_constructed fired modifier_naval_construction_boom on any constructed hull (including supply ships and torpedo boats), and completing je_naval_arms_race stacked naval_overhaul_arms_race_momentum (+10% shipyard throughput) with modifier_naval_arms_race_focus (+10%) for +20% total. (Restricted construction boom to capital ships/carriers and cleared momentum upon event resolution.)

AI Architecture

Risk
AI Complexity Injection Overwrite & Blindness in Simulator Budget Model

zz_naval_overhaul_strategy.txt duplicated Vanilla's value = 20 and law blocks instead of cleanly adding +12 onto Vanilla/Kuromi's 10 baseline, omitting law_diplomatic_navy. Worse, sim_overhaul.py:340,640 read a nonexistent cost field (always 0.0), completely disabling complexity budget enforcement in offline AI validation. (Remediated to additive add = 12 in script and ordinal modification-level budgeting in sim_overhaul.py.)

Architecture Governance

Domain Architecture

Risk
Asymmetric Counter Gap Against Torpedo Boat Destroyers & Era Mismatch

ship_mod_secondary_torpedo_defense and ship_mod_secondary_heavy_aa targeted torpedo_boat and destroyer while omitting torpedo_boat_destroyer—leaving a blind spot despite capital ships carrying a -0.5/-0.66 penalty against it. Conversely, utility_mod_aa_director was available on 1870s torpedo boats despite its WWII anti-aircraft role. (Remediated in both script files.)

Risk
Submarine Firing Rate & Anti-Capital Multiplier Masked by Broken Simulator Math

When evaluated under Victoria 3 1.15.1's true flat armor subtraction (concept_ship_armor_desc) and damage-reduction modifiers, baseline ship_type_submarine (readiness_gain = 28, 3.0x vs capital, crit_mult = +1.0) overwhelmed even screened 3 DN + 6 Sonar DD fleets (0.65 exchange ratio). Re-tuning submarine stats (hp = 1100, readiness_gain = 16, crit = 0.18 / +0.75, 2.5x vs capital) restored the 4-pole counter loop (unscreened 0.22 → screened 4.45).

API Architecture

Strength
Engine Modifier Contract Alignment

All modifier keys across common/ are validated against Victoria 3 1.15.1's common/modifier_type_definitions/*.txt contract, and zz_naval_overhaul_missions.txt coordinates additively with Vanilla's base ship_visibility_mult = -0.25 on convoy raiding.

Concern
Missing clicksound Contract on Custom Core Modifications

All custom modifications in 02_hull_and_secondary_modifications.txt omitted Vanilla's clicksound attribute required by ship_designer_popup.gui:1082 ([ShipModificationType.GetClickSound]). (Added Vanilla Designer SFX paths to all custom modifications.)

Architecture Fitness Metrics

Strength
Automated Regression Gate in sim_overhaul.py --assert-mode

The upgraded fitness suite enforces zero VFS merge warnings, zero full-file conflict paths, 100% UTF-8 BOM compliance across .txt/.yml/.gui, Vanilla 1.15.1 modifier contract verification, zero utility stacking across all 22 ships, tech-tree closure for all defaults, 100% bilingual YAML key symmetry/completeness, AI complexity budget adherence, and 6-step combat exchange thresholds.

Common Anti-Patterns

Concern
Dead Code & Phantom Define References

Baseline code contained unused artifacts including naval_overhaul_ai_utility_base in zz_naval_overhaul_script_values.txt:124-127, naval_overhaul_victory_prestige in 01_naval_overhaul_modifiers.txt:27-30, ship_mod_secondary_heavy_casemate in localization, and nonexistent defines (NAVAL_ARMOR_MITIGATION_DIVISOR, BLOCKADE_SUPPLY_NETWORK_IMPACT_SCALING) in sim_overhaul.py. (All removed.)

Testability

Risk
High-Fidelity Gap in Baseline Simulator Combat & VFS Models

Baseline sim_overhaul.py diverged from Victoria 3 1.15.1 on four critical axes: (1) hyperbolic armor mitigation instead of flat subtraction + zero-damage bounce withdrawal; (2) ignoring ship_suffered_hull_damage_mult, ship_suffered_crew_damage_mult, and ship_suffered_crit_chance_mult; (3) computing accuracy / 100.0; and (4) evaluating cost = 0.0 instead of modification levels. (All four corrected in sim_overhaul.py, though unit tests for the parser itself remain absent.)

Evolvability

Concern
Maintenance Burden of Full 00_ship_types.txt Override

Modifying or adding ships in future Victoria 3 patches requires manually diffing 2,708 lines in 00_ship_types.txt rather than maintaining targeted per-ship INJECT: / REPLACE: blocks or a generated compatibility patch for Naval Treaty Expanded.

Strength
Modular Overlay Strategy for Future Phase 3 Features

Keeping defines, laws, missions, AI strategies, and events in cleanly prefixed mod files makes Phase 3 extensions (Port/Shipyard PM rebalancing, Naval Battle Conditions) straightforward to layer in without rewriting existing mechanics.
